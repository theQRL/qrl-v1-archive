# Archive tools

`qrl-archive` implements `inspect`, exact stored-byte `export`, `verify --mode structural`, `compare`, and `compare-native-state`. It reads the pinned QRL v1 LevelDB height mapping, copies each stored protobuf value without serializing it again, and writes the [version 1 block stream](../schemas/qrl-v1-block-stream-v1.md). Export verifies its staged output before making the output directory visible. The export report marks consensus, native final-state and derived-data verification as false. The separate [native state comparison](../schemas/qrl-v1-native-state-compare-v1.md) checks exact QRL state-version-3 records on two stopped copies; it does not replay consensus.

Open a **disposable, stopped LevelDB working copy**. Verify the untouched custodial copy against its recorded file manifest first, then make a fresh working clone. LevelDB takes an exclusive lock and can rewrite its log or manifest during recovery and compact data files while reading. Never point the tool at a live node or a custodial snapshot. The exporter pins one logical snapshot for all reads and refuses an occupied LevelDB lock, a changing source tip, changed live genesis/fork/terminal mapping or block bytes, or a source tip different from the declared terminal height. Its JSON report notes observed file churn as a diagnostic; file churn alone is not a failure because LevelDB can cause it internally. Verify each independent source and compare their canonical block bytes before accepting a release. Structural verification does not establish consensus validity.

The LevelDB library must decode Snappy-compressed historical `.ldb` files. A Python `plyvel` import or version check alone does not establish that its linked LevelDB library has Snappy support. Check the linked library and perform a real block-read preflight on a disposable copy. A build without Snappy fails with a source-read error; do not classify that alone as source corruption. Preserve the exact runtime and linked library in the rehearsal release.

Each `--json-report` path is append-only: the command refuses to replace an existing report. Use a fresh path for each attempt and keep failed reports with the run evidence.

Example interface, with values supplied from an independently reviewed source report:

```text
qrl-archive inspect --source-db STOPPED_WORKING_COPY/state --network-id testnet --expect-genesis-hash G --json-report inspect.json
qrl-archive export --source-db STOPPED_WORKING_COPY/state --network-id testnet --genesis-hash G --fork-height F --fork-hash FORK_HASH --terminal-height H --terminal-hash T --run-id RUN_ID --output canonical --json-report export.json
qrl-archive verify --canonical canonical --expect-network-id testnet --expect-genesis-hash G --expect-fork-height F --expect-fork-hash FORK_HASH --expect-terminal-height H --expect-terminal-hash T --mode structural --json-report verify.json
qrl-archive compare --canonical-a source-a/canonical --canonical-b source-b/canonical --expect-network-id testnet --expect-genesis-hash G --expect-fork-height F --expect-fork-hash FORK_HASH --expect-terminal-height H --expect-terminal-hash T --json-report compare.json
qrl-archive compare-native-state --source-db-a source-a/working/state --source-db-b source-b/working/state --expect-network-id testnet --expect-genesis-hash G --expect-fork-height F --expect-fork-hash FORK_HASH --expect-terminal-height H --expect-terminal-hash T --json-report native-state-compare.json
```

`compare` requires distinct canonical directories and verifies both against the same operator-supplied network, genesis, fork and terminal anchors. It compares each stored protobuf value at every height, regardless of shard boundaries or run IDs. Its [deterministic report](../schemas/qrl-v1-comparison-report-v1.md) gives whole-stream SHA-256 and SHA3-256 digests and the first differing height and block digests. A difference exits with code 5. Corrupt or changed input fails structural verification instead. The report does not prove that the two exports came from independent nodes; preserve the source and custody records separately.

`compare-native-state` requires two distinct disposable LevelDB working directories. It classifies every key, compares exact application-state key/value bytes, and reports SHA-256 and SHA3-256 digests by category. It excludes known auxiliary block, transaction and cache records from state equality; `fork_state`, unknown keys and state versions other than 3 fail closed. A state difference exits with code 5 and a report naming the first mismatched key. It does not prove consensus validity or source independence. Do not use it on a custodial copy or a running node.

The LevelDB does not store a trusted network name. `--network-id` is an operator claim tied to the independently checked genesis hash. `consensus` and `full` modes fail closed. The [SQLite v1 deriver](../schemas/qrl-v1-sqlite-v1.md) builds an inspectable `.partial.sqlite` file from verified canonical shards. It preserves exact nested transaction bytes, recipient legs and address roles. Its CLI exits `4` with status `INCOMPLETE`, and its metadata says `release_ready=false`, because consensus replay and canonical final-state reconstruction are still missing. An optional stopped native state working copy supplies comparison balances. Parquet, the fixture runner and a release-ready SQLite mode remain to be built. The unsigned R2 smoke objects in `fixtures/` do not pass any archive gate.

For a point-in-time snapshot, the current `terminal_height` and `terminal_hash` field names identify the last included block. They do not imply that the network has stopped. The source network may continue above the archived cutoff.

The exporter and verifier pin the shipped `qrl.proto`, generated `qrl_pb2.py` file, and binding descriptor by SHA-256; all three digests are required in `shards.json` and emitted in command reports. The protobuf source is unchanged across QRL v4.0.1 through v4.0.11, but real mainnet LevelDB fixtures and a live mainnet build check are still required before mainnet use. Exact stored bytes remain the canonical record even when the decoder is updated.
